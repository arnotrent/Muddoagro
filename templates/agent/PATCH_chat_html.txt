### PATCH — templates/agent/chat.html ###

1) Add a CSRF token tag somewhere in the page so the browser gets the
   csrftoken cookie (chat.js reads it for send/mark-read requests).
   This page currently has ZERO {% csrf_token %} tags anywhere, so on a
   fresh session the agent could never send or mark-read a message —
   same root cause as the admin side, just on the other end of the chat.

   Right after the opening <body ...> tag, add:

       {% csrf_token %}

   (Django renders this as a hidden <input>, which is harmless sitting
   unused in the page — its only real job here is to make Django set the
   csrftoken cookie on page load.)


2) WhatsApp-style bubble tails + delivered ticks, without WhatsApp's green
   branding (uses your existing --orange var, which is now mint-dark via
   theme_vars.css). Add to the <style> block:

    .msg-row{margin-bottom:2px}
    .msg-row.received .msg-bubble{position:relative;border-bottom-left-radius:4px}
    .msg-row.sent .msg-bubble{position:relative;border-bottom-right-radius:4px}
    .msg-row.received .msg-bubble::before{
      content:'';position:absolute;left:-6px;bottom:0;width:0;height:0;
      border:6px solid transparent;border-right-color:var(--bg-card);border-bottom:none;
    }
    .msg-row.sent .msg-bubble::before{
      content:'';position:absolute;right:-6px;bottom:0;width:0;height:0;
      border:6px solid transparent;border-left-color:var(--orange);border-bottom:none;
    }
    .chat-date-sep{text-align:center;font-size:.72rem;color:var(--text-muted);
      background:var(--bg-alt);display:inline-block;padding:3px 12px;border-radius:100px;
      margin:10px auto;align-self:center}

3) (Optional) Group consecutive messages from the same day under a date
   separator like real messengers do. This needs a small JS change in
   chat.js's appendMessage() — if you want this, say so and I'll wire it
   in; skipping it for now keeps the patch surface small since it touches
   shared code used by both chat pages.
